How pooling works

More data, not more certainty than it supports.

Trials are paired within their own run by task and attempt; no pair crosses runs. The pooled exact test counts every paired disagreement from every run, and pass rates, intervals, and medians cover all pooled trials. Each run is also analyzed on its own above, so a run that points the other way stays visible.

Pooling assumes the runs measured the same thing. Different configurations, agents, instruction digests, task refs, or ContextTest versions are flagged above rather than refused, because growing a sample over time is the point—but each one is a reason the runs might not be exchangeable.
